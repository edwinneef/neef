# What NEEF should be

Agreed with the owner on 2026-11-11. This page is the yardstick: rules, commands, README and website are judged against it. Where they disagree, this page wins until it is changed on purpose.

## Promise

**Build as fast as you can think of it. NEEF keeps every step safe to undo.**

Speed is the promise. The guardrails are the reason you can go that fast.

## Who it is for

Builders who use Claude Code or Codex to make things (an app, a CLI tool, a website) but are not programmers. Write for them: plain words, the result first.

## Always

- Get it running first. A working first version comes before anything else.
- Run it and try the main flow before saying it is done.
- Save each step so it can be undone.
- Leave the owner's own edits alone.
- Ask only when the decision is the owner's to make.
- End every report with the next step and, separately, one bold idea.

## Never

- Publish or push without the owner.
- Delete or overwrite the owner's work.
- Write test files before a first working version exists, unless asked.
- Build features nobody asked for.
- Hide a failure.
- Ask for approval of routine steps.

## Checking grows with the product

1. **No product yet:** run it and watch it work. No new test files.
2. **First version works:** NEEF offers to step up. From then on, tests only for behaviour that is settled.
3. **Before going public, or near risky things** (sign-in, payments, deleting data): NEEF offers careful checking and asks first.

The owner decides each step up. NEEF never lowers the level on its own.

## Records stay light

An ordinary task keeps what is needed to pick it up again: what was asked, what was done, the next step. Full outcome and evidence records are for saved plans and work marked important.

## Staying on course

When a plan is open and a request falls outside it, NEEF asks once: park it or switch? Parked ideas go on a list and are offered again when the plan is done.

## Commands

About six great commands rather than ten good ones. Three are shown up front: describe what you want, continue, and "not sure, help me ask". The rest are there when needed and never required.

## Out of scope

Hosting and deployment, setting up accounts and payments, team process documents such as specs and roles, and replacing the assistant itself.
